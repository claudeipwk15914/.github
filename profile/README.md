<p>给 Claude 选住宅 IP 服务器，卡住人的往往不是预算，而是销售页上那几行含糊的字：带宽写 100M 却没说共享还是独享，节点列了五个城市却没说哪个有货，售后写 7×24 却没说节假日谁值班。这篇按真实沟通的顺序，把六个最常被问到的问题挨个说清，每题都给一个能当场执行的动作。下单前把这些问明白，比事后换服务商省事得多。</p>

<h2>一、标称 100M 的带宽，为什么两个号同时用就卡</h2>
<p>先分清三个口径：端口速率、保证带宽、以及同宿主机上其他用户的分摊。中低价位卖的几乎都是端口速率，也就是网卡理论上能跑多快，而不是你能稳定拿到多少。Claude 的网页对话本身不费带宽，一次流式回复的峰值也就几百 Kbps，卡顿通常不是总量不够，而是排队和丢包。</p>
<h3>iperf3 与 mtr 各测一遍</h3>
<p>拿到机器先跑 <code>iperf3 -c 测速节点 -t 30 -P 4</code>，看四线程合计能跑多少；再跑 <code>mtr -rwc 100 目标域名</code>，重点盯第 8 到第 12 跳的丢包是否逐跳累积。前者反映总量，后者反映路径质量。总量达标但末段丢包超过 3%，问题在路径不在带宽，升套餐解决不了。</p>
<h3>晚高峰单独测一轮</h3>
<p>白天的数字没有参考价值。把测试固定在本地 20:00 到 23:00，连测五天。若下行从 80Mbps 掉到 15Mbps 以下，基本可以判定超售，白天好看只是因为没人用。</p>

<h2>二、节点放在哪个城市，要不要和账号注册地一致</h2>
<p>城市选择先看两件事：目标服务商的接入点在哪，以及你的账号长期在哪个地区活动。Claude 的边缘节点在北美和欧洲较密，从洛杉矶或法兰克福过去通常三十到六十毫秒，从东南亚绕行则容易上百。</p>
<h3>注册地与出口地不一致的代价</h3>
<p>账号资料写美国、出口在新加坡、浏览器时区又是东八区，这三项凑在一起，平台侧看到的是一个拼装出来的身份。不是必然出事，而是每次异常都少一条能自证一致的线索。稳妥做法是让出口地区、账单地址、界面语言落在同一国家。</p>
<h3>多地区怎么排优先级</h3>
<p>主账号绑主出口，副账号可以分散但要各自固定，别让同一个账号在两周内跨三个国家。城市级差异通常小于国家级差异，除非做长文生成这类延迟敏感的任务，否则不必为同国不同城多付钱。</p>

<h2>三、售后响应速度，付钱前怎么试出来</h2>
<p>售后的真实水平只在出故障时体现，但有两件事在付款前就能观察到：工单系统里有没有历史回复记录，以及客服能不能回答具体参数而不是复制话术。</p>

<h3>用三个技术问题当筛子</h3>
<p>问"你们上游 transit 是哪两家"，答得出来的通常自建或至少转售一手资源；问"IP 更换周期和费用"，含糊其辞的多半要临时找上游申请；问"凌晨三点掉线谁处理"，回答里出现具体值班城市和时限的，才算有真运维。</p>
<h3>故障责任要先分清</h3>

<h2>四、超售怎么在开通前就看出苗头</h2>
<p>三个信号值得警惕：价格明显低于同城同配置的均价；销售不肯给测试 IP；官网上没有明确的服务等级数字，只有"稳定"两个字。前两条是商业信号，第三条是追责信号，没有数字就没有依据。</p>
<h3>要一个 24 小时试用</h3>
<p>正规服务商通常愿意给短时试用或按天计费。试用期别只看能不能打开网页，要在晚高峰跑一次 iperf3，再用 <code>curl -o /dev/null -w "%{time_total}\n" https://claude.ai</code> 连打二十次，看耗时分布是集中在 0.3 秒还是散到 2 秒以上。分布比均值更能说明问题。</p>

<h2>五、合同里哪几句决定半年后能不能顺利续</h2>
<p>续费环节最容易出问题的是三处：价格有效期、IP 变更条款、退款计算方式。写"首年优惠"的，第二年往往按原价跳一档；写"IP 资源随上游调整"的，意味着你付的固定地址可能在某个季度被换掉。</p>
<h3>把口头承诺落成文字</h3>
<p>谈好的"一年不涨价""IP 不变更"要写进订单备注或合同附件，同时保留截图。真出争议时聊天记录多数平台可以作补充依据，但优先级低于合同正文，关键条款别只停在对话里。</p>

<h2>六、什么情况该换服务商，而不是换套餐</h2>
<p>判断标准很朴素：同一个问题连续两个月复发，且每次都得靠你自己绕过去。路径丢包、超售限速、IP 频繁变更属于资源侧问题，加钱升级同一条线基本无效。反过来说，只是某个时段慢、换个时段就正常，多半是国际段拥塞，换一家同城的也未必更好。</p>
<h3>迁移成本也要算进去</h3>
<p>换服务商意味着重新绑定出口、重新观察一周、账号侧再经历一次环境变化。所以先确认问题出在资源侧再决定搬。把过去三个月的故障记录摊开，同类问题占比过半，才值得动。</p>

<h2>常见问答</h2>
<h3>标称独享带宽，实际还需要和别人抢吗？</h3>
<p>答：独享指你这台机器到上游交换机这一段不与他人共享，但上游的国际出口仍是公共资源。独享能保证本地不排队，不能保证跨境段不拥塞，晚高峰仍然要实测。</p>
<h3>节点城市越多越好吗？</h3>
<p>答：不是。节点多意味着维护面广，小服务商铺五个城市往往每个都不深。对 Claude 这类集中在北美和欧洲的服务，两三个稳定城市比五个半吊子节点更实用。</p>
<h3>售后写 7×24，怎么确认不是机器人？</h3>
<p>答：提一个需要现场判断的问题，比如"我这台机器 mtr 第 9 跳开始丢包，你们上游这一段走的是哪家"，机器人会答非所问，真人会给路径或要求你补 traceroute。</p>
<h3>先月付还是直接年付？</h3>
<p>答：第一次合作建议月付，跑满一个完整计费周期、经历过一次晚高峰和一次故障处理之后，再考虑年付。年付的折扣通常抵不上一次踩坑的迁移成本。</p>
